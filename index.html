01 / NOW

Unified Item Orchestrator

Vendors and partners used to reach Target's catalog through several separate ingestion paths. UIO replaces them with one route. Each submitted item becomes a durable, long-running Temporal workflow that drives 35 systems until the item is sellable.

  • Activity-level retries and timeouts, idempotent activities, and saga-style compensation when a step fails halfway.
  • Workflow state survives worker restarts and downstream outages, so no item is lost mid-flight.
  • A Core Data Service on horizontally sharded PostgreSQL with Citus is the platform's system of record.

02 / NOW

Scaling Temporal from 5M to 10M workflows a day

Today Temporal keeps every workflow's history in one PostgreSQL store. To double throughput, I am moving that persistence layer to horizontally sharded Cassandra, so history writes spread across a ring of nodes.

  • Temporal history shards
  • Cassandra
  • PostgreSQL
  • Capacity planning
03

Item Agent Orchestrator

A multi-agent platform built on Google ADK. A decision-model classifier routes each item request to the right agent. Agents coordinate over the A2A protocol, and the same Temporal platform behind UIO runs their long-running tasks with the same durability and retries.

  • Google ADK
  • A2A protocol
  • Decision-model classifier
  • Temporal
04

LLM attribute enrichment with a human in the loop

I led the taxonomy and item-data side of an initiative that uses LLMs to derive and enrich item attributes, so items are set up faster and are easier to find. I built the item MDM's handling of a new AI-generated attribute group by myself, across both rollout phases.

  • A flag in the taxonomy platform controls which attributes AI may derive; I made it editable.
  • Taxonomists review AI taxonomy recommendations in the taxonomy platform, and their feedback flows back to the models.
